# S0.2 — Dependências Nest 11 + TypeScript 5

**Não crie `main.ts` nem módulos nesta fatia.** Só dependências e o mínimo de `tsconfig` para o Nest compilar depois.

## Objetivo

Instalar Nest 11 estável, `class-validator`, `class-transformer`, e TypeScript 5. O app ainda sobe pelo Express (`server.ts`).

## Comandos

Na raiz de `gas-e-agua-backend`:

```bash
npm install @nestjs/common@^11 @nestjs/core@^11 @nestjs/platform-express@^11 class-validator class-transformer rxjs
npm install -D @nestjs/testing@^11 typescript@^5
```

`reflect-metadata` já existe. Não reinstalar se já estiver em `dependencies`.

**Não instalar:** `@nestjs/passport`, `@nestjs/swagger`, `@nestjs/typeorm`, `@nestjs/bullmq`, `@nestjs/schedule`, `nestjs-zod`, `@nestjs/cli` (cli só em S9).

## tsconfig.json

Já tem `experimentalDecorators` e `emitDecoratorMetadata`. **Não ligue `strict`.**

Se o `tsc` novo reclamar só do Nest, acrescente **apenas** o que for necessário para `npm run typecheck` passar. Não reorganize `paths`.

## Express 5

Nest 11 pode subir `express` para v5. Não mude paths da API. Rode os testes. Se a suíte quebrar por roteamento (`/*`, opcionais), **pare e pergunte** — não “corrija” URL.

## Não alterar

`src/` (nenhum arquivo de aplicação). `Dockerfile`. `start` / `dev`. `babel.config.js`.

## Gates

```bash
npm run typecheck
npm test
```

Os dois têm que passar como antes desta fatia.

## Pronto quando

- `package.json` tem `@nestjs/common`, `@nestjs/core`, `@nestjs/platform-express` na linha 11.x
- `typescript` em `devDependencies` é 5.x
- `class-validator` e `class-transformer` instalados
- testes verdes
- nenhum `src/**` modificado

## Parar

Marque S0.2. Não abra S0.3.
