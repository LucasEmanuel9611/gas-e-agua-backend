# S0.3 — Bootstrap Nest em volta do Express

O Express continua dono de **todas** as rotas. O Nest só envolve o mesmo `app` e passa a ser o processo.

## Objetivo

`src/main.ts` sobe o server. `dev` e `start` apontam para ele. Workers e cron continuam iguais aos de `server.ts`.

## Pode criar

### `src/app.module.ts`

```ts
import { Module } from "@nestjs/common";

@Module({
  imports: [],
  controllers: [],
  providers: [],
})
export class AppModule {}
```

Nenhum módulo de domínio.

### `src/main.ts`

Copiar a lógica de `src/shared/infra/http/server.ts` (listen, workers, cron, SIGTERM/SIGINT, unhandledRejection, uncaughtException). Trocar `app.listen` por Nest + adapter.

```ts
import "reflect-metadata";
import { NestFactory } from "@nestjs/core";
import { ExpressAdapter } from "@nestjs/platform-express";

import { AppModule } from "./app.module";
import { LoggerService } from "./shared/services/LoggerService";
import { queueManager } from "./shared/infra/queues/QueueManager";
import { runScheduledTasks } from "./shared/infra/tasks";
import { app, port } from "./shared/infra/http/app";

async function bootstrap() {
  const nestApplication = await NestFactory.create(
    AppModule,
    new ExpressAdapter(app)
  );

  nestApplication.enableShutdownHooks();

  await nestApplication.listen(port);

  LoggerService.info(`🚀 Server is running on port ${port}`, {
    port,
    environment: process.env.NODE_ENV,
    timestamp: new Date().toISOString(),
  });

  await queueManager.initializeWorkers();
  runScheduledTasks();
}

bootstrap();

process.on("SIGTERM", async () => {
  LoggerService.info("SIGTERM received, shutting down gracefully");
  await queueManager.shutdownWorkers();
  process.exit(0);
});

process.on("SIGINT", async () => {
  LoggerService.info("SIGINT received, shutting down gracefully");
  await queueManager.shutdownWorkers();
  process.exit(0);
});

process.on("unhandledRejection", (reason, promise) => {
  LoggerService.error("Unhandled Rejection at:", new Error(String(reason)), {
    promise: promise.toString(),
  });
});

process.on("uncaughtException", (error) => {
  LoggerService.error("Uncaught Exception:", error);
  process.exit(1);
});
```

Ajuste imports se o eslint de ordem do projeto exigir o mesmo padrão dos outros arquivos (`@shared` etc.). Não mude comportamento.

## Pode alterar

### `src/shared/infra/http/server.ts`

Substituir o conteúdo por um único reexport para não deixar um segundo `listen`:

```ts
import "../../../main";
```

Ninguém deve importar `server.ts` para subir o app. `start` passa a ser `main.js`.

### `package.json` scripts

- `start`: `node dist/main.js`
- `dev`: o comando atual, trocando o path final  
  `src/shared/infra/http/server.ts` → `src/main.ts`

Não mudar `build`. Continua Babel.

### `Dockerfile`

Não mudar `CMD ["npm", "start"]` (já usa o script). Não mudar HEALTHCHECK.

## Não alterar

Rotas, middlewares, `app.ts` (além do que já exporta `app` e `port`), Prisma, filas, testes, `babel.config.js`.

Não registrar `ValidationPipe`, filter nem guard nesta fatia (isso é S0.4).

## Gates

```bash
npm run typecheck
npm test
```

Smoke manual (se o ambiente local estiver de pé):

```bash
# depois de npm run dev
curl -s -o /dev/null -w "%{http_code}" http://localhost:3333/health
```

Esperado: `200` ou `503` (DB down), nunca 404.

## Pronto quando

- Processo sobe por `src/main.ts`
- `start` = `node dist/main.js`
- `server.ts` não chama `app.listen`
- Rotas Express inalteradas
- testes verdes
